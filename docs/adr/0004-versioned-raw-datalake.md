# Raw layer is an append-only versioned datalake guarded by a load signature

Every unit extract writes a new versioned table `raw.<source>_<YYYYMMDD>_<n>` (per-source counter that resets daily) and no version is ever dropped, making raw an append-only datalake rather than a set of clobbered fixed tables. A `loaded_files` log (filename, filesize, modified_at, loaded_at, loaded_to) records each load action; a file whose signature `(filename, filesize, modified_at)` is already logged is skipped unless the extract run passes `-f`, in which case it reloads and appends a new version plus a new log row. The log is append-only with no uniqueness constraint — duplicated signatures are expected when a file is force-reloaded, and `loaded_to` disambiguates them.

This makes re-extraction recurring (a fixed cast bug, a changed file) a matter of appending a corrected version, with provenance preserved for recovery, instead of silently overwriting history. The trade-off is storage: many versions accumulate, accepted for a small registry. Boundary files land in a single non-versioned `raw.boundaries` table (load-if-not-exists, `country_iso='DEU'`, `name`, `level` 0=country outline / 1=regions+EEZ / 2=districts / 3=municipalities, `area` computed in km² via PostGIS) since boundaries are reference data, not records.
